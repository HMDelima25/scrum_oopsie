HOPE, Inc. · Sprint 1 · Natalia Ortiz

Authentication wireframes

Design review artifact. Sample data only. Form actions are disabled; no accounts, sessions or records are created.

Flow: Register → pending approval → invitation → set password → Login. Forgot password → email link → reset password → Login.

Login

Forgot password · Create account

Invalid credentials: “Email or password is incorrect.” Pending: “Your account is awaiting approval.” Blocked: “Your account is blocked. Contact an administrator.” Never enter the workspace until the server confirms a session.

Register

Required fields and duplicate email have inline errors. Successful server response: account created as User, pending approval. First-password setup uses the approved one-time link; current backend instead requires name + password, so the Developer must resolve this contract gap.

Forgot password

After server confirmation use neutral copy: “If this account is eligible, check your email.” Include submitting, network failure and retry. Do not claim email delivery while the backend only logs tokens.

Set first password

One-time token from an approved invitation; expired/reused token offers a new link. On confirmed success return to login. Dedicated set-password endpoint is missing in current main.

Reset password

Token read from the reset link, never manually typed. Show mismatch and invalid/expired/reused token; request a fresh link. On server success return to login; do not create a session implicitly.

Review at desktop and mobile widths. Backend enforcement remains the Developer’s responsibility.
